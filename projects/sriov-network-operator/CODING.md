# SR-IOV Network Operator — Coding

Coding conventions, architecture patterns, and common pitfalls for contributing
to the `k8snetworkplumbingwg/sriov-network-operator` repository.

---

## Repository Layout

| Directory | Purpose |
|-----------|---------|
| `main.go` | Operator manager entry point (controller-runtime based) |
| `api/v1/` | CRD Go types (`sriovnetwork.openshift.io` group), deepcopy, apply configurations |
| `controllers/` | Reconciliation controllers for all CRDs |
| `cmd/sriov-network-config-daemon/` | Config daemon binary — runs on each node to configure SR-IOV devices |
| `cmd/webhook/` | Admission webhook binary — validates and mutates SR-IOV CRs |
| `cmd/sriov-network-operator-config-cleanup/` | Cleanup binary for operator uninstall |
| `pkg/` | Shared library code (see breakdown below) |
| `bindata/` | Embedded YAML manifests deployed by the operator at runtime |
| `config/` | Kustomize and CRD base manifests (generated by controller-gen) |
| `deployment/` | Helm chart for deploying the operator |
| `hack/` | Build scripts, formatting, boilerplate, e2e helpers |
| `test/` | E2E and conformance tests |
| `doc/` | Project documentation |
| `deploy/` | Additional deployment resources |
| `ci/` | CI-specific configurations |

### `pkg/` Sub-packages

| Package | Purpose |
|---------|---------|
| `pkg/apply/` | Kubernetes resource apply/merge utilities |
| `pkg/consts/` | Shared constants (feature gate names, platform strings, paths) |
| `pkg/daemon/` | Config daemon logic — device configuration, reconciliation loop |
| `pkg/drain/` | Node drain coordination logic |
| `pkg/featuregate/` | Feature gate framework (thread-safe, map-based) |
| `pkg/helper/` | Host helper interface — abstraction for host operations |
| `pkg/host/` | Host interaction implementations (sriov, kernel, network, udev, systemd, etc.) |
| `pkg/log/` | Logging configuration (controller-runtime zap logger) |
| `pkg/orchestrator/` | VF allocation and orchestration |
| `pkg/platform/` | Platform detection (Kubernetes vs. OpenShift) |
| `pkg/plugins/` | Vendor-specific plugins (generic, Intel, Mellanox, K8s, virtual) |
| `pkg/render/` | Template rendering for bindata manifests |
| `pkg/status/` | Status reporting utilities |
| `pkg/utils/` | General utilities (PCI, network, cluster helpers) |
| `pkg/vars/` | Global variable definitions |
| `pkg/vendors/` | Vendor-specific logic (Mellanox firmware handling) |
| `pkg/version/` | Build version injection |
| `pkg/webhook/` | Webhook validation and mutation logic |

## CRD Types

All CRDs belong to the `sriovnetwork.openshift.io` API group and are defined in
`api/v1/`:

| Kind | File | Purpose |
|------|------|---------|
| `SriovNetwork` | `sriovnetwork_types.go` | Defines an SR-IOV network attachment |
| `SriovIBNetwork` | `sriovibnetwork_types.go` | InfiniBand SR-IOV network attachment |
| `OvsNetwork` | `ovsnetwork_types.go` | OVS-based network attachment |
| `SriovNetworkNodePolicy` | `sriovnetworknodepolicy_types.go` | Policy for VF configuration on nodes |
| `SriovNetworkNodeState` | `sriovnetworknodestate_types.go` | Per-node SR-IOV device state (status) |
| `SriovNetworkPoolConfig` | `sriovnetworkpoolconfig_types.go` | Pool-level configuration |
| `SriovOperatorConfig` | `sriovoperatorconfig_types.go` | Operator-wide configuration and feature gates |

### CRD change workflow

1. Edit the type definitions in `api/v1/*_types.go`.
2. Run `make generate` to regenerate deepcopy and apply configuration code.
3. Run `make manifests` to regenerate CRD YAML in `config/crd/bases/`.
4. Verify with `make check-manifests` that the config folder is up to date.

## Code Generation

The operator uses `controller-gen` for code generation.

| Command | Generated output |
|---------|------------------|
| `make generate` | `zz_generated.deepcopy.go`, apply configurations in `api/v1/applyconfiguration/` |
| `make manifests` | CRD YAML in `config/crd/bases/`, copies to `deployment/sriov-network-operator-chart/crds/` |
| `make mock-generate` | Mock implementations via `go generate ./...` (uber/mock mockgen) |

**Never hand-edit generated files.** Files prefixed with `zz_generated.` are
auto-generated — edit the source types and re-run the generator.

## Feature Gates

New features should be gated using the `pkg/featuregate` package:

1. Define the constant in `pkg/consts/constants.go`.
2. Add the default state in `pkg/featuregate/featuregate.go` (`DefaultFeatureStates` map).
3. Use `featureGate.IsEnabled(consts.MyFeatureGate)` in runtime code.
4. The operator exposes feature gates via the `SriovOperatorConfig` CR.

Current feature gates include: `ParallelNicConfig`, `ResourceInjectorMatchCondition`,
`MetricsExporter`, `ManageSoftwareBridges`, `BlockDevicePluginUntilConfigured`,
`MellanoxFirmwareReset`.

## Boilerplate

Every Go source file must start with the Apache 2.0 license boilerplate.
The template is in `hack/boilerplate.go.txt`. The header format is:

```go
/*
Copyright <year>.

Licensed under the Apache License, Version 2.0 (the "License");
...
*/
```

## Import Conventions

The project uses `goimports` with local prefix ordering configured in
`.golangci.yml`:

```
local-prefixes:
  - github.com/k8snetworkplumbingwg/sriov-network-operator
```

Import ordering: **stdlib → external → k8s.io / sigs.k8s.io → project-local**.

Ginkgo and Gomega are dot-imported in test files:

```go
import (
    . "github.com/onsi/ginkgo/v2"
    . "github.com/onsi/gomega"
)
```

## Logging

The operator uses **controller-runtime's zap logger** (configured in `pkg/log/`):

```go
import "sigs.k8s.io/controller-runtime/pkg/log"

log := log.Log.WithName("controller-name")
log.Info("message", "key", value)
log.Error(err, "message", "key", value)
```

- Do **not** use `fmt.Printf`, `log.Printf`, or `klog` directly.
- Log levels map to the operator's `LogLevel` setting (0=info, 1=debug, 2=trace).
- Stacktraces are disabled by default (level set to `DPanicLevel`).

---

## Error Handling

- Wrap errors with context using `fmt.Errorf("context: %w", err)`.
- Controllers return errors to trigger requeue by controller-runtime.
- Use `ctrl.Result{RequeueAfter: duration}` for delayed requeue.
- Do not swallow errors silently — either return them or log at Error level.

## Platform-Aware Code

The operator supports both **Kubernetes** and **OpenShift**:

- Platform is detected via `pkg/platform/` and stored in `pkg/vars/`.
- Use `vars.ClusterType` to branch on platform-specific behavior.
- The `CLUSTER_TYPE` environment variable controls platform in tests.
- Many unit tests run twice: once with `CLUSTER_TYPE=kubernetes`, once with
  `CLUSTER_TYPE=openshift`.

## Bindata / Embedded Manifests

The `bindata/` directory contains YAML templates that the operator renders and
applies at runtime:

| Subdirectory | Content |
|-------------|---------|
| `bindata/manifests/daemon/` | Config daemon DaemonSet |
| `bindata/manifests/webhook/` | Webhook resources |
| `bindata/manifests/operator-webhook/` | Operator webhook resources |
| `bindata/manifests/plugins/` | Device plugin DaemonSets |
| `bindata/manifests/cni-config/` | CNI configuration |
| `bindata/manifests/switchdev-config/` | Switchdev configuration |
| `bindata/manifests/sriov-config-service/` | Host service files |
| `bindata/manifests/metrics-exporter/` | Metrics exporter resources |
| `bindata/scripts/` | Shell scripts for host configuration |

These are rendered via `pkg/render/` with template variables and applied by the
controllers.

## Testing Patterns

### Unit tests

- Tests live alongside the code: `*_test.go` next to the source file.
- **Ginkgo v2 + Gomega** is the standard test framework.
- Controllers use `envtest` (controller-runtime's test environment with a real
  etcd + apiserver) — set up in `controllers/suite_test.go`.
- Unit tests require `CLUSTER_TYPE` env var (`kubernetes` or `openshift`).
- Mocks are generated with uber/mock (`mockgen`) via `make mock-generate`.

### Running unit tests

```bash
# Test a specific package (both platforms)
CLUSTER_TYPE=kubernetes make test-pkg
CLUSTER_TYPE=openshift make test-pkg

# Test a specific subdirectory
CLUSTER_TYPE=kubernetes make test-controllers
CLUSTER_TYPE=kubernetes make test-cmd
CLUSTER_TYPE=kubernetes make test-api
```

The `test-%` Makefile pattern runs `go test` on the matching directory, excluding
`/mock` and `/pkg/client` paths.

### E2E / Conformance tests

- Conformance tests live in `test/conformance/tests/` — Ginkgo-based, run against
  real clusters with SR-IOV hardware.
- E2E tests in `test/e2e/` cover operator behavior end-to-end.
- E2E runs require SR-IOV-capable hardware (self-hosted runners with `sriov` label).
- Use `make test-e2e-conformance-virtual-k8s-cluster-ci` for virtual K8s cluster tests.
- Use `make test-e2e-conformance-virtual-ocp-cluster-ci` for virtual OCP cluster tests.

### Shell script tests

```bash
make test-bindata-scripts   # Tests shell scripts in bindata/ using fakechroot
```

## Common Pitfalls

1. **Forgetting `make generate` after type changes** — Any modification to
   `api/v1/*_types.go` requires `make generate` followed by `make manifests`.
   CI checks this with `make check-manifests`.
2. **Missing `CLUSTER_TYPE` env var** — Unit tests will fail or behave
   unexpectedly without `CLUSTER_TYPE=kubernetes` or `CLUSTER_TYPE=openshift`.
3. **Editing generated files** — Files prefixed with `zz_generated.` and the
   `api/v1/applyconfiguration/` directory are auto-generated. Edit source types
   and re-run `make generate`.
4. **Stale CRD manifests** — After `make manifests`, the generated YAML is
   copied to both `config/crd/bases/` and
   `deployment/sriov-network-operator-chart/crds/`. CI verifies this with
   `make check-manifests`.
5. **Missing boilerplate** — New files without the Apache 2.0 license header
   from `hack/boilerplate.go.txt` may be flagged.
6. **Bindata changes without testing** — Shell scripts in `bindata/scripts/`
   have dedicated tests via `make test-bindata-scripts`. Don't forget to run
   them after modifying scripts.
7. **Vendor-specific plugin registration** — New vendor plugins must implement
   the `VendorPlugin` interface in `pkg/plugins/plugin.go` and be registered
   in the plugin factory.
8. **Mock staleness** — After changing interfaces used by mocks, re-run
   `make mock-generate` to update generated mocks.
9. **fmt target uses containerized gofmt** — `make fmt` runs inside a container
   via `hack/go-fmt.sh`. Use `make fmt-code` for direct local `go fmt ./...`.
